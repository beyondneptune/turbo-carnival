## Honest observations

1. **64 of 146 architectures (44%) generalize cleanly.** That's actually a
   high pass rate — most of these are linear or moderately-regularized
   models. Boosted trees with high tree count overfit consistently on
   this 54k-bar dataset.

2. **No architecture exceeds 0.873 test AUC.** The ceiling is real and
   imposed by the data. More architectures, more compute, more agents do
   NOT push the ceiling.

3. **Top pass-gate models are remarkably similar in test AUC** (0.849 –
   0.868), spanning 8 different algorithmic families. This suggests the
   features (10 hand-engineered ones from `shared/data.py`) carry roughly
   0.86 AUC of regime-volatility signal, and which model captures it
   matters less than getting the features right.

4. **Custom Haiku-agent designs that passed the gate**:
   - `107_bart_style_additive` (0.859 / +0.024) — BART-style sequential trees with manual shrinkage
   - `115_isotonic_calibrated_chain` (0.830 / +0.017) — per-feature isotonic regression chained into LR
   - `116_multitask_regime_plus_direction` (0.815 / +0.009) — dual-head NN predicting regime + direction
   - `120_bayesian_ridge_sigmoid` (0.802 / +0.004) — Bayesian conjugate-prior regression
   - `121_poly_kernel_ridge` (0.812 / +0.017) — degree-3 polynomial kernel ridge
   - `125_mlp_strong_l2_regularization` (0.830 / +0.009) — alpha=1.0 MLP + 5-seed average
   - `131_prototype_knn` (0.742 / +0.049) — KMeans centroids per class
   - `132_gradient_boosted_logreg_stack` (0.802 / +0.004) — Ridge weak learners
   - `141_hard_negative_mining_mlp` (0.846 / +0.020) — model-feedback example curation
   - `143_power_transform_nb` (0.831 / -0.001) — Yeo-Johnson + GaussianNB
   - `144_nb_lr_geometric_blend` (0.828 / +0.001) — geometric mean of NB and LR
   - `145_sparse_lr_saga_screening` (0.799 / +0.006) — aggressive L1 then refit
   - 12 of the 43 Haiku-agent designs pass the gate (28%)

5. **Architectures that demonstrably calibrate better**:
   - `135_calibrated_cv_lgbm` — lab-best Brier 0.0815 (fail overfit but best calibration)
   - `129_asymmetric_fp_penalty_lgbm` — lab-best precision@top1% 77.1%

## Connection to the ATHENA v1 deployment

The lab's purpose was research/proposals for the post-freeze cycle, NOT
mid-cycle changes. The ATHENA v1 candidate spec in
`data/strategy_specs/candidates/athena_v1_lane{1,2}.json` uses the
`001_logreg`-equivalent LogisticRegression as its regime gate (which is
in the pass-gate set at 0.799 AUC / +0.007 gap — a robust, well-calibrated
linear model). The lab confirms: the LogReg gate inside ATHENA v1 is a
**near-optimal pass-gate choice** for the bar-level regime classification
task; deeper models squeeze ~7 more AUC points but overfit.

For Day 2 (2026-05-12) deployment, the **honest recommendation remains**:
ATHENA v1 (with LogReg + autoencoder cascade) as designed, OR pivot to
CARRY (0DTE credit spreads) per the 10-Opus debate's structurally-strongest
finding. The lab does NOT change that recommendation.

- No reinforcement learning. Sample size is too low.
- No feature engineering beyond the 10 baseline features.
- No deployed model. **Live host (`scripts/alpaca_max_hft_host.py`) is untouched.**
